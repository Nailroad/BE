# Nailroad 주간 회고

매주 프로젝트에서 실제로 겪은 일을 돌아보고, 각자의 경험에서 나온 주제를 함께 토의합니다. 회고 기록은 `weekly-review` 브랜치에 주차별로 누적합니다.

## 회고 문서

| 팀원 | 개인 회고 |
| --- | --- |
| 동현 | [동현의 주간 회고](weekly-review/동현/README.md) |
| 서영 | [서영의 주간 회고](weekly-review/서영/README.md) |

[ACE 작성 템플릿](weekly-review/template.md)을 복사해 개인 README에 새 주차를 추가합니다.

```text
README.md                     # 회고 규칙과 개인별 링크
weekly-review/
├── template.md               # ACE 작성 템플릿
├── 동현/
│   └── README.md             # 동현의 주차별 회고
└── 서영/
    └── README.md             # 서영의 주차별 회고
```

## 회고 진행 방식

### 1. 개인 README에 회고 작성하기

각자 개인 README 하나에 주차별 회고를 추가합니다. 주차와 기간을 적고, 아래 ACE 형식으로 작성합니다.

- **A · Achievement | 이번 주에 이룬 것**
  마무리한 작업, 해결한 문제, 새로 배운 점을 적습니다.
- **C · Challenge | 이번 주에 어려웠던 것**
  어떤 상황에서 막혔고 어떻게 대응했는지 적습니다.
- **E · Expectation | 다음 주에 기대하는 변화**
  다음 주에 어떤 점이 나아졌으면 하는지 적습니다. 회고에서 직접 해보기로 한 일이 있다면 함께 기록합니다.

### 2. 토의 주제 하나씩 공유하기

각자 회고에서 팀원들과 이야기하고 싶은 주제 1개를 고릅니다. 회고 전에 해당 주차의 README 링크와 토의 질문을 노션에 올립니다.

해결하기 어려웠던 문제, 다른 의견이 궁금한 결정, 팀에도 적용해 보고 싶은 좋은 경험, 흥미로웠던 개념 등을 주제로 가져올 수 있습니다.

### 3. 경험을 바탕으로 함께 토의하기

각자 주제를 고른 배경과 당시 상황을 짧게 소개합니다. 그중 팀이 함께 고민할 주제 1~2개를 골라 비슷한 경험과 다른 접근 방법을 나눕니다.

피드백은 당시 상황과 선택에 초점을 맞추고, 각 방법을 우리 프로젝트에 적용했을 때의 장단점을 이야기합니다.

### 4. 토의 결과 기록하기

새로 알게 된 점과 합의한 내용을 노션에 짧게 남깁니다. 다음 주에 시도할 개선 사항이 있다면 누가 무엇을 할지 정하고, 각자의 E에도 반영합니다. 다음 회고에서 실제로 어떤 변화가 있었는지 확인하고 기록합니다.

## 작성 및 공유 방법

- 개인 회고는 각자 본인 폴더의 README에 주차별로 추가합니다.
- 작성 전에 `weekly-review` 브랜치로 전환하고 원격의 최신 변경을 받아옵니다.
- 회고 작성과 수정은 이슈 생성 없이 진행하며, 브랜치명과 커밋 메시지에서 이슈번호를 생략합니다.
- 커밋 메시지는 `docs: 동현 1주차 회고 작성`, `docs: 서영 1주차 토의 내용 반영`처럼 작성합니다.
- 작성한 회고는 `weekly-review` 브랜치에 직접 푸시해 공유합니다.
